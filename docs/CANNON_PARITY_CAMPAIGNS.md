# Cannon parity and module-proof campaigns

CannonLab must answer two different questions before it synthesizes another serious cannon:

1. What mechanics does the target server actually run?
2. Which cannon modules have causal evidence under that profile?

`plan-cannon-parity-campaign.py` pairs every private ExtremeCraft fingerprint dimension with a pinned public-Sakura reference experiment. Safe identity, spawn, redstone and motion probes run first. Paste-limit, durability, regeneration and OSRB probes remain explicitly higher-risk and cannot be silently folded into ordinary cannon tests.

`plan-cannon-module-campaign.py` expands a requested architecture into a dependency-ordered proof plan. A one-shot request therefore produces charge, payload, sand release, hammer, hybrid and slab-bust stages before composition. Evidence already meeting the desired promotion level is reused by exact module ID; everything else remains blocked behind its own acceptance evidence.

These planners do not generate cannon geometry and do not count as observations. They prevent a monolithic scratch build from skipping the mechanics fingerprint or the module proof graph.
